第 1 步 · 基础信息（逻辑模型层）

这一层决定用户看到的名字与计费口径。上架、下架、改卖价，改的是这一层；不改，用户仍调同一个名。

默认沿用运营表 Base_slug（如 deepseek/deepseek-v4-flash）。斜杠前是命名习惯，不是渠道。不强制 vectoree/ 前缀——是否统一前缀待与 leader 拍板。
⚠ 已确认方向：对外显示名改为必填。Plaza 标题为空会 fallback 成 vendor/model 斜杠串，破坏 B2C 体验；最终以研发确认后台「添加模型」弹窗字段必填性为准。
计费模式决定计价单位（文本/视觉/音频 Token → 1M tokens；图像 → 张；视频 → 秒；TTS → 1K 字符；转写 → 分钟；按次 → 次）。「透传上游成本」即后台原文，对应定价方式里的「跟随上游」。

第 3 步 · 调度与容错（多路怎么挑 / 挂了切谁）

仅当该逻辑模型绑了 ≥1 条路时有意义。对应后台「模型调度策略 / 容错策略」页。默认：价格优先 + 故障转移开。

文档明确：默认价格优先，不是按优先级/权重；「加权分流」才用权重随机。本表单之前误写成「按优先级/权重」已修正。
故障转移名单 = 本模型已启用且上游ID齐全的「备1 / 备2」绑定（第 2 步收集）。

第 4 步 · 价格（逻辑模型卖价层）

成本 / 售价来自运营表「供应商折扣 / 我们设置的折扣」。下分三层：① 基础售价（必填） → ② 区域价（可选标准维度） → ③ 高级运营策略（非常规，默认收起）。调用类型（输入 / 输出 / 缓存）属基础计费拆解，不单列成策略。

必填 ① 基础售价（成本 / 售价 / 利差）
Token 模态天然区分输入 / 输出 / 缓存输入单价，从 provider.csv 本地点选或手填。这是基础计费结构，不是与价格策略并列的配置项。
可选 ② 区域价（标准维度）
同一逻辑模型可挂多区域价（来自 region刊例.csv）。区域必须从标准词表下拉选择（43 个，如 Australia East / Japan East / West Europe），不可手填，避免 "Australia East" 与 "澳洲东部" 不一致、无法与刊例表 join。无区域行＝全局统一价。

第 5 步 · 预检 & 验收

  • ① 渠道健康（密钥池可连通） 未检查
  • ② 上游 ID 齐全（主+备都绑了） 未检查
  • ③ 调度策略已配置 未检查
  • ④ 容错策略已配置（熔断阈值/冷却） 未检查
  • ⑤ 价格完整（三态已定、无异常） 未检查
  • ⑥ 限时折扣有效期（非「待定」） 未检查
  • ⑦ 试打一条（真实调用成功） 未检查

易混纠正（来自概念文档）
· 供应商 ≠ 渠道：供应商是商务概念，一家可拆多条渠道；但本运营表里「供应商」列直接当渠道用（已谈定的直连账）。
· slug 里的 deepseek/ ≠ 渠道：只是命名，货源以绑定指向的渠道为准。
· 多 Key ≠ 多渠道：key 是额度/轮换/单 key 失效，换云换区域走渠道+绑定。
· 绑定权重 ≠ 渠道权重：渠道权重/优先级是全局属性（对所有经此渠道的模型），绑定权重/优先级只管「这个商品走这条路」。
· OpenRouter 内部的 Together/Fireworks 不建模为渠道。
