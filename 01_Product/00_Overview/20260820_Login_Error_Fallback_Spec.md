# 登录错误兜底规范（Login Error Fallback Spec）

> 背景：2026-08-20 在 vectoree.ai 登录页实测发现两类**裸系统错误**直接透传给终端用户：
> 1. `X-Project-Id is not accepted by System Auth`（卡在网关/系统鉴权层）
> 2. `invaild credential`（拼写错误；卡在凭据校验层，且为 `invalid` 的错拼）
>
> 两者均表现**间歇性 + 刷新/等待后重试自愈**，说明根因在**线上后端/鉴权链路的稳定性**，而非账号密码或前端配置。
> 经代码核查，上述字符串**不存在于 pm-workspace 的静态原型代码中**，确认来自线上后端、被线上前端原样透传。

## 1. 核心原则

1. **绝不向用户暴露系统内部术语与原始报错**。用户看到的只能是"对他有意义、可操作"的文案。
2. **原始错误必须完整落日志**（含 correlation id / request id），供研发定位，但不进 UI。
3. **安全优先**：登录失败统一说"账号或密码错误"，不区分是账号不存在还是密码错，防止被用于撞库/账号枚举。
4. **稳定性问题归后端，体验问题归前端**：前端负责"接住任何错误并转译为友好文案"；后端负责"减少错误发生 + 返回结构化错误码"。

## 2. 内部错误 → 用户文案 映射表

| 内部错误（后端日志/原始响应） | 触发阶段 | 用户应看到的文案 | 是否暴露根因 |
|------|------|------|------|
| `X-Project-Id is not accepted by System Auth` | 网关/系统鉴权层 | 「登录服务暂时异常，请稍后重试」 | 否 |
| `invalid credential`（含 `invaild` 错拼） | 凭据校验层 | 「账号或密码错误，请重试」+「忘记密码」入口 | 否 |
| 网络超时 / 5xx / 网关错误 | 任意 | 「网络异常，请检查连接后重试」 | 否 |
| 账号被锁定 / 风控拦截 | 凭据校验后 | 「账号已被临时锁定，请稍后或联系支持」 | 部分（不暴露规则） |
| 邮箱未验证 | 凭据校验后 | 「请先验证邮箱，验证邮件已重新发送」 | 否 |

> 拼写红线：线上文案中出现 `invaild` 属 P2 文案 Bug，必须修正为 `invalid` 并最终统一为中文兜底文案，禁止英文裸错误上线。

## 3. 前端（线上前端）责任清单

- [ ] **错误兜底层**：所有登录请求 `catch` 任意异常/非 2xx，统一映射到第 2 节文案，禁止 `JSON.stringify(err)` 或原始 message 直接展示。
- [ ] **错误码优先**：优先读取后端返回的结构化 `error.code`（如 `AUTH_PROJECT_REJECTED` / `INVALID_CREDENTIAL`），无 code 时按 HTTP 状态兜底。
- [ ] **重试策略**：对"服务暂时异常"类（5xx / 网关 / project 拒绝），前端做**指数退避自动重试（最多 2 次，1s/2s）**，仍失败再提示用户手动重试——可显著降低间歇性故障的用户感知。
- [ ] **交互态**：登录按钮在请求中 `disabled` + loading；失败不清除已输入账号（仅清空密码），减少用户挫败。
- [ ] **文案本地化**：所有兜底文案走 i18n，中文为默认。

## 4. 后端责任清单（根因侧）

- [ ] **结构化错误响应**：统一返回 `{ code, message(内部), requestId }`，`message` 仅供日志，UI 只用 `code` 映射。
- [ ] **稳定性排查**（针对间歇性自愈现象，按概率排）：
  1. 负载均衡后是否存在**不健康/未就绪实例**（坏实例轮询命中）；
  2. Serverless / 容器**冷启动**导致首次调用 env/连接未就绪；
  3. 鉴权依赖（用户库 / 令牌服务）**超时抖动**；
  4. **限流 / 连接池耗尽**（高峰时段）。
- [ ] **可观测性**：登录失败按 `error.code` 打点，附实例 ID 与 requestId，便于与失败时间对齐定位坏实例。

## 5. 严重度与提单建议

- 间歇性但**完全阻断登录** → 后端稳定性 Bug，建议 **P1**（影响转化与留存，且在真实用户侧已复现）。
- 裸错误透传（体验） → 前端 **P2**，与 P1 并行修复。
- 提单必备信息：报错时间戳、报错文案、重试第几次成功、是否集中在高峰/部署后。

## 6. 验收标准（DoD）

- [ ] 任意登录路径下，用户**不会再看到** `X-Project-Id` / `invalid` / `invaild` 等原始报错。
- [ ] 所有失败场景覆盖第 2 节映射表，文案已本地化。
- [ ] 线上前端对"服务暂时异常"类错误已接入自动重试。
- [ ] 后端错误响应含 `code` + `requestId`，登录失败有可观测打点。
- [ ] `invaild` 拼写错误从全量文案中清除。
