# Vectoree 产品拆解报告
> 调研对象：https://vectoree.ai/  |  调研日期：2026-08-13  |  视角：产品专家

---

## 1. 产品定位

### 1.1 一句话描述
**一站式 Agent 开发与上线平台**：模型、鉴权、数据库、支付、部署「六块积木 + 一条装配线」，帮开发者/团队跳过胶水代码，从 0 到上线 Agent。

### 1.2 Slogan & 核心主张
- 主 Slogan：**Ship Your Agent**（官网标题）
- 主文案：**"零基础，即刻上线 Agent"**；**"一站式 Agent 开发平台——模型、鉴权、数据库、部署，一个账号全搞定"**
- 定价主张：**"为胶水付费，不为席位付费"**（核心差异化）
- 部署主张：**"别再拼胶水，开始交付。你的 Agent 可能在这页滚完之前就上线了。"**

### 1.3 目标用户分层
| 层级 | 用户角色 | 核心诉求 | 对应档位 |
|------|---------|---------|---------|
| L1 初学者 / 独立开发者 | 个人开发者、独立黑客 | 快速试错、0 成本上手、免信用卡 | Free |
| L2 小型团队 / 创业公司 | CTO、全栈工程师、Agent 产品团队 | 无限项目、自定义域名、B2B2C 认证+支付闭环 | Pro |
| L3 中大型企业 | 企业 IT、数字化团队 | SSO/SCIM、团队协作、审计、优先路由、共享余额 | Enterprise |

### 1.4 产品差异化（vs 纯模型聚合平台如 OpenRouter / Together AI）
- **不是模型 API 聚合，而是 Agent 全栈 PaaS**：从模型接入一路管到「向你的 C 端用户收费」
- **胶水层是产品核心**：6 块积木说同一种 SDK，用户不用接 5 家 OAuth / Webhook
- **B2B2C 能力是杀手锏**：认证（给你的用户登录）+ 支付（向你的用户收费）是 OpenRouter 类产品不做的事
- **装配线隐喻**：每个 Agent 走同一条装配回路（选模型→装技能→接认证→设支付→部署）

### 1.5 品牌识别
- 吉祥物：Vee（贯穿全站的小机器人形象）
- 视觉系统：积木块隐喻 / 装配线隐喻
- 公司主体：VECTOREE INC.（© 2026）
- 双语支持：中/英切换

## 2. 产品概述

### 2.1 解决的核心问题
开发者要上线一个 Agent 产品，通常需要自行拼装 5+ 套 SaaS：
1. 模型供应商 API（多家签合同接 API）
2. 用户认证系统（邮箱/Google OAuth、会话、组织）
3. 支付计费系统（Stripe 接入、发票、催收、分账）
4. 数据存储（Postgres、向量库、文件存储、行级安全）
5. 部署基础设施（域名、CI/CD、子域托管）

Vectoree 把以上 5 块 + 模板/技能两块做成「6 块积木 + 一条装配线」，用统一 SDK 和控制台贯穿。

### 2.2 核心价值主张（对用户可量化）
- **接入成本**：原本 2-4 周的胶水代码工作 → 缩短到小时级 / 天级
- **计费模式**：模型 Tokens 按成本结算，不加价转售，仅收平台费
- **免费门槛**：无需信用卡、每月 100 万 tokens、直接开跑
- **所有权保留**：模板一键 fork，仓库是你的、基建是你的（vendor lock-in 控制感）

### 2.3 不做什么（隐含边界）
- 不自研大模型（全部来自 5 家第三方供应商）
- 不做底层云基础设施（构建在主流云之上）
- 不做端侧 AI / 本地推理（面向云端部署的 Agent）

## 3. 功能模块拆解

核心架构隐喻：**「一个控制台，六块积木，一条装配线」**

### 3.1 模块全景图
```
                    ┌──────────────────────────────┐
                    │       Vectoree 控制台        │
                    │  (一个账号 / 一个 SDK)       │
                    └──────────────┬───────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   ┌────▼────┐  ┌────▼────┐  ┌───▼────┐  ┌───▼────┐  ┌───▼────┐  ┌────▼────┐
   │ 模型广场 │  │  模板   │  │技能中心│  │  认证  │  │  支付  │  │数据与存储│
   └─────────┘  └─────────┘  └────────┘  └────────┘  └────────┘  └─────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │       装配线 (Assembly)      │
                    │  选模 → 装技能 → 认证 → 支付 → 部署 │
                    └──────────────────────────────┘
```

### 3.2 模块详细拆解

#### 🧱 M1：模型广场 (Model Marketplace)
| 维度 | 内容 |
|------|------|
| 定位 | 多模型统一接入层，替代用户挨个接厂商 |
| 核心能力 | 5 家供应商、36 个模型，一把 API Key |
| Playground | 支持模型「对打」测试，同 Prompt 跑多家对比 |
| 路由策略 | 按成本 / 延迟智能路由；一行代码切换模型 |
| 计费策略 | Tokens 按**成本结算**，不加价转售（平台只收平台费） |

#### 🧱 M2：模板 (Templates)
| 维度 | 内容 |
|------|------|
| 定位 | 生产级 Agent / 应用脚手架，降低冷启动成本 |
| 核心能力 | 一键 Fork → 一键部署 |
| 所有权 | 仓库归用户、基建归用户（Vectoree 管管道） |
| 分层 | 社区模板（Free）+ Pro 模板（推测） |

#### 🧱 M3：技能中心 (Skills Hub)
| 维度 | 内容 |
|------|------|
| 定位 | Agent 的能力扩展生态（插件系统） |
| 安装方式 | 像装包一样装进 Agent |
| 技能类型 | ① 经纪 API（Broker API）② MCP ③ CLI 工具 |
| 营销文案示例 | "午饭前就能发出一个量化研究 Agent" |

#### 🧱 M4：认证 (Auth)
| 维度 | 内容 |
|------|------|
| 定位 | **B2B2C** 能力核心：给「你的用户」做登录，不是给你做登录 |
| 开箱即用方式 | 邮箱 + Google 登录 |
| 高级能力 | 会话管理、组织（Organization）、B2B2C 多租户 |
| 替代方案 | 手写 Auth0 / Clerk / 自研 → 省掉 |

#### 🧱 M5：支付 (Payments)
| 维度 | 内容 |
|------|------|
| 定位 | Agent 商业化闭环核心：帮助平台方「向自己的用户收费」 |
| 计费模式 | 订阅费 / 按量计费，**用户自己定价** |
| Vectoree 负责 | 开票、催收、分账（把钱结算给平台方） |
| 替代方案 | 手写 Stripe 接入、发票系统、催收流程 → 省掉 |

#### 🧱 M6：数据与存储 (Data & Storage)
| 维度 | 内容 |
|------|------|
| 存储组合 | Postgres（关系型）+ 文件存储 + 向量索引（Embedding） |
| 接入方式 | 从第一天就接入 Agent，统一 SDK |
| 企业级特性 | 数据迁移、行级安全（Row-level Security） |
| 替代方案 | 手写 Supabase / Neon + Pinecone / Weaviate → 省掉 |

### 3.3 装配线（横向流程能力）
> 不是独立模块，是串联 6 块积木的开发/上线流程

- **统一 SDK**：6 块积木「说同一种 SDK」，不用读 5 份文档
- **统一控制台**：所有积木的配置、监控、用量都在一个后台
- **部署流水线**：Fork 模板 → 配置 → 部署到 `vectoree.app` 子域 / 自定义域名
- **用量分析**：Pro 档支持自定义域名 + 用量看板

## 4. 定价 & 商业化策略

### 4.1 三档定价结构
| 档位 | 价格 (推测) | 核心权益边界 |
|------|-----------|-------------|
| 🆓 Free | $0 / 无需信用卡 | 1 个项目 · 每月 100 万 tokens · 模型广场 + Playground · 社区模板 · 部署到 vectoree.app 子域 |
| ⚡ Pro | 月付 (联系销售或按平台费比例) | Free 全部 + **无限项目与模型** + 技能中心任意安装 + **认证 + 支付（B2B2C 核心）** + 自定义域名 · 用量分析 |
| 🏢 Enterprise | 年付 / 定制 | Pro 全部 + 成员、角色、审计日志 + SSO/SCIM + 优先路由 + 共享余额 |

### 4.2 商业化亮点
1. **「胶水而非席位」定价哲学**：不强按人头卖 seat，卖平台能力（团队协作放在企业档，SaaS 常规做法）
2. **成本透明**：Tokens 不加价转售，平台费单独收 → 建立信任
3. **转化漏斗清晰**：
   - Free（零门槛体验 6 块积木）→ Pro（要 B2B2C/无限项目）→ Enterprise（要 SSO/审计/优先路由）

## 5. 核心用户路径

### 5.1 路径 1：独立开发者「0 成本跑通 Agent」（Free 档）
```
第 1 步 访问 vectoree.ai
        ↓ 点击"免费开始 / 开始构建 →"，无需信用卡
第 2 步 进入控制台 → 浏览「模型广场」→ Playground 试跑 36 个模型
        ↓ 选定模型，生成 API Key
第 3 步 Fork 一个社区「模板」→ 一键部署
        ↓ 获得 vectoree.app 子域，Agent 已上线
第 4 步 查看 tokens 用量（100 万免费额度）
        ↓ 超过额度 → 考虑升级 Pro
```

### 5.2 路径 2：创业团队「做 B2B2C Agent 产品并收费」（Pro 档 → 核心转化路径）
```
第 1 步 从 Free 升级 Pro → 解锁无限项目 & 认证 & 支付
        ↓
第 2 步 选模板 / 从零构建
        ├── 模型广场：选模型 + 路由策略（成本 or 延迟）
        ├── 技能中心：安装量化 / 搜索 / 邮件 等技能
        └── 数据存储：接入 Postgres + 向量索引
        ↓
第 3 步 配置 B2B2C 闭环（Vectoree 杀手级能力）
        ├── 认证：开启邮箱/Google 登录（给"平台方的用户"用）
        └── 支付：平台方自己定价（订阅/按量），Vectoree 管开票/催收/分账
        ↓
第 4 步 部署 → 绑定自定义域名 → 用量分析
        ↓
第 5 步 规模化 → 用户增长 → 考虑 Enterprise（团队成员/SSO/审计）
```

### 5.3 路径 3：企业客户「安全合规 + 团队协作」
```
联系销售 → 开通 Enterprise 档
    ├── 团队管理：成员、角色、权限
    ├── 审计日志（合规必需）
    ├── SSO/SCIM（企业账号打通）
    ├── 优先路由（稳定性保障）
    └── 共享余额（统一结算）
```

## 7. 关键观察 & 潜在机会（产品视角）

### 7.1 为什么这套模式能跑通
1. **Agent 开发 = 胶水开发**是行业共识痛点，Vectoree 直接命中
2. **B2B2C 认证 + 支付**把"开发者做 Agent 赚不到钱"的最后一公里补上了（多数同类平台只管到开发者调 API，不管他怎么向 C 端收费）
3. **装配线隐喻**降低心智负担：新用户只要理解「6 块积木 + 一条线」
4. **成本透明**在模型加价严重的赛道里是很强的信任牌

### 7.2 风险 / 待验证点
1. **模型供应商合规**：是否所有 5 家厂商都允许转售 / API 代理？需确认 License 条款
2. **平台费率 vs 价值感知**：Pro 档价格如果太高，小团队可能宁愿自己接 Stripe + Auth0；需看定价细节
3. **用户数据主权**：存储、向量、支付数据在 Vectoree 手中，企业客户是否接受？（Enterprise 档的承诺需更明确）
4. **技能生态冷启动**：M3 技能中心的技能数量和质量决定平台粘性，初期需要官方强力供给模板和技能
