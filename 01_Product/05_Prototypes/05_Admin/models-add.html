逻辑模型层 × 渠道层 × 绑定层 × 价格组件化。一次走完 5 步，自动生成路由 + 容错策略。

本流程吸收了 8.25 运营表对齐结论 与 模型网关概念文档：① 逻辑模型 = 用户调用的名字（卖价挂这层）② 渠道 = 哪本账、哪个入口 ③ 绑定 = 商品×渠道×上游 ID（一条可走的路）④ 调度 + 容错 = 多路怎么挑、挂了切谁。

第 1 步 · 基础信息（逻辑模型层）

这一层决定用户看到的名字与计费口径。改这一层不改，用户仍调同一个名。

默认沿用运营表 Base_slug。斜杠前是命名习惯，不是渠道。不强制 vectoree/ 前缀——是否统一前缀待拍板。
⚠ 待拍板：对外 slug 是否统一包 vectoree/ 前缀。运营表当前用厂商/型号原名，若强行改前缀会影响「是否调用=调供应商」的货源追踪，建议先沿用原名。
计量单位已归一：阿里 wan 模型按 second 计（官网口径有误，以运营表修正为准）。单位选错会导致单价与计费偏差。

第 2 步 · 货源与渠道（渠道层 + 绑定层）

决定「走哪条管道」。数据来自运营表「供应商 / 供应商备 1-3 / 是否调用」列。一个商品可绑 1..N 条路。

上游模型 ID = 发给上游的真实名字。默认 = 对外 slug；直连时可能是厂商部署名（如 deepseek-v4-pro-0816-us）。
新建渠道配置（base_url + 密钥，需测通）
⚠ 密钥脱敏显示（sk-****1234）+ 权限控制；多 key 是「同渠道换钥匙/额度」，不是换云。
系统将自动生成：channelBindings（商品×渠道×上游 ID）+ 路由策略（按优先级/权重排序）+ 容错策略（故障转移名单，会话亲和性钉在渠道上）。取代现状「0 个故障转移步骤」。

第 3 步 · 价格组件化（逻辑模型卖价层）

成本/售价来自运营表「供应商折扣 / 我们设置的折扣」；维度覆盖会议结论：波峰波谷 / 区域 / 调用类型 / 限时折扣。

价格维度（可叠加，对应会议 4 维度）
① 波峰 / 波谷（分时）
② 区域（来自 region 刊例.csv）
同一逻辑模型可挂多区域价；无区域行 = 全局统一价。
③ 调用类型（Input / Output / Cached）
对齐 provider.csv 的 Input / Output / Cached Input / 其它单位。
④ 限时折扣 （来自 update.csv：wan3.0 限时折扣、时间待定）
不填有效期 = 长期有效；「时间待定」必须填预计区间，否则预检拦截上架。
选「跟随上游」后不填价，系统取主渠道供应商结算价，自动同步波动。适合价格随上游频繁变动的模型。
开启免费/零价开关，用户调用不扣费（适合引流 / 内部模型）。

第 4 步 · 预检 & 验收

系统自动跑 5 项检查；通过后才能上架。

  • ① 渠道健康（密钥可连通）未检查
  • ② 上游 ID 齐全（主+备都绑了）未检查
  • ③ 价格完整（三态已定、无异常）未检查
  • ④ 限时折扣有效期（非「待定」）未检查
  • ⑤ 试打一条（真实调用成功）未检查

第 5 步 · 上架

预检全部通过。确认本次提交会自动生成路由策略 + 容错策略。
