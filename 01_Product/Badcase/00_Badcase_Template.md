# Badcase 标准录入模板

> 用途：统一登记 Vectoree 产品运行中的劣质 / 异常案例（Badcase），打通「发现 → 归因 → 修复 → 回归」的质量闭环。
> 适用：网关 / 模型路由、Auth、Database、Storage、计费、安全合规等任意线上异常。
> 写法：复制本文件为 `BC-YYYYMMDD-X.md`（编号规则见 `01_Badcase_Index.md`），按 `[ ]` 占位符逐项填写；`> 注释：` 为填写指引，落库后可保留或删除。
> 关联：所有 Badcase 在 `01_Badcase_Index.md` 汇总登记；本模板是 `01_Product/Badcase/` 模块的唯一录入母版。

---

## 【基础信息】

> 注释：一条 Badcase 的「身份卡」。编号全局唯一，一经分配不再复用；严重等级决定响应优先级与升级路径。

| 字段 | 填写值 | 说明 |
| - | - | - |
| 编号 | `BC-[YYYYMMDD]-[X]` | 日期 + 当日流水号，例：`BC-20260903-001` |
| 提交人 | [姓名 / 工号] | 发现并登记者 |
| 发现时间 | `YYYY-MM-DD HH:mm` | 首次观测到异常的时间 |
| 严重等级 | `[P0 / P1 / P2 / P3]` | 勾选一项（见下） |

**严重等级定义（单选）：**

- [ ] **P0** — 致命：生产阻断、资金损失、安全事件、全量不可用
- [ ] **P1** — 严重：核心功能受损、主链路失败、部分用户受影响
- [ ] **P2** — 一般：局部异常、可绕行、主要影响体验
- [ ] **P3** — 轻微：边缘场景、提示性、低影响

> 注释：复现与排查的「现场」。Request ID / Trace ID 是研发拉日志的必备凭证，线上问题务必填全；无法获取时标注「N/A」并说明原因。

- **涉及业务模块 / 产品形态**：[网关 Model Plaza / Auth / Database / Storage / Billing / 安全合规 / 其他]
- **模型 / 渠道 / URL**：[模型 ID、Provider 渠道、触发接口或页面 URL]
- **用户 / 租户 ID**：[受影响用户或组织（org）标识；内部问题填 `internal`]
- **关联 Request ID / Trace ID**：[网关 / 服务链路追踪 ID，排查凭证]
- **环境**：[生产 / 预发 / 本地 demo / 其他]

> 注释：用「输入 → 实际 → 预期」三段把问题讲清。输入尽量贴原始 Payload（脱敏后），实际 / 预期各写一条，便于研发秒懂差异。

- **触发输入（Input / Payload）**：
  ```
  [贴出触发请求的原文或关键字段，敏感信息脱敏]
  ```
- **实际输出（Actual）**：
  ```
  [系统真实返回的错误码 / 报文 / 行为，例：HTTP 404 / 空响应 / 计费金额偏差]
  ```
- **预期输出（Expected）**：
  ```
  [正确情况下应返回的结果，例：命中模型并返回 200 / 金额与用量一致]
  ```

## 【归因分类】

> 注释：先勾错误类型（可多选），再写根因。根因分析要落到「为什么发生」，而非「现象是什么」。

**错误类型（可多选）：**

- [ ] 边缘输入 — 异常 / 超长 / 含特殊字符的输入未兜底
- [ ] 路由映射失效 — 模型 ID、渠道、Key 映射错误或丢失
- [ ] 风控拦截 — 限流 / 鉴权 / 安全策略误杀或漏放
- [ ] 模型质量 — 输出错误、幻觉、格式不符、质量不达标
- [ ] 商业计费 — 计价、精度、扣费、账单偏差
- [ ] 安全合规 — 越权、数据泄露、合规违规

**根因分析（Root Cause Analysis）：**

```
[定位到的根本原因；附排查路径 / 关键日志片段 / 复现步骤]
[区分「触发条件」与「根因」：例如「模型 ID 含尾随空格（触发）→ 网关 trim 缺失导致路由 key 不匹配（根因）」]
```

## 【解决与闭环】

> 注释：这条 Badcase 的「终点」。状态按下方枚举推进；若补充进评测集，未来同类问题可被自动回归拦住。

| 字段 | 填写值 | 说明 |
| - | - | - |
| 处理状态 | `[OPEN / IN_PROGRESS / FIXED / VERIFIED / WONTFIX]` | 见下 |
| 负责人 | [研发 / 对应模块 Owner] | 当前处理人 |
| 修复方案摘要 | [一句话说明怎么修的] | 例：网关对模型 ID 做 trim 归一化 |
| 是否补充入测试集（Eval Benchmark） | `[是 / 否]` | 是则填下方 Case ID |
| 评测案例 ID | `[eval-xxxx / N/A]` | 入库后的回归用例编号 |
| 回归验证结果 | `[PASS / FAIL / 待验证]` | 修复后复跑结论 |

**处理状态枚举：**

- `OPEN` — 待处理：已登记，未开始
- `IN_PROGRESS` — 处理中：排查 / 修复进行中
- `FIXED` — 已修复：代码合入，待回归验证
- `VERIFIED` — 已验证闭环：回归通过，可关闭
- `WONTFIX` — 暂不处理：评估后决定不改（需填原因）

**闭环记录（按需追加）：**

```
[修复 PR / 提交链接]
[回归验证时间 + 结论]
[是否同步更新了相关文档 / 监控告警]
```
