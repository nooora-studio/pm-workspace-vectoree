## 4 流程与逻辑

> ASCII 树给整体判断逻辑（到处都能看、不依赖渲染）；Mermaid 补状态机与时序（这两种关系用文字说不清）。**不是每篇都要图：说不清才画，不凑数。**

### 4.1 主流程（ASCII 分支树）

```
[触发入口]
  ↓
[判断 1]
  ├─ 分支 A → [结果 A]
  │             ↓
  │          [后续判断 / 结束态]
  └─ 分支 B → [结果 B]
                ↓
             [兜底 / 异常分支]
```

### 4.2 状态机（Mermaid）

```mermaid
stateDiagram-v2
    [*] --> 状态A
    状态A --> 状态B: 触发条件
    状态B --> 状态A: 回退条件
    状态B --> [*]
```

**状态定义表：**

| 状态 | 含义 | 进入条件 | 停留多久 | 可能的下一状态 |
| - | - | - | - | - |
| | | | | |

> 状态机是后端建模的依据。凡是前端 HTML 里**能出现多个不同形态**的地方（loading / 空态 / 错误态 / 多种成功态），就应该是一个明确的状态，写进这张表。**前端把三种不同情况合并成一种视觉呈现时（常见于 demo），必须在本文拆开分别定义**——否则研发会以为只有一种。

### 4.3 关键时序（Mermaid，可选）

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant B as 后端
    U->>F: 操作
    F->>B: 请求
    B-->>F: 响应
```

### 4.4 判断逻辑与分支条件

| # | 判断点 | 判定条件 | 条件成立 | 条件不成立 |
| - | - | - | - | - |
