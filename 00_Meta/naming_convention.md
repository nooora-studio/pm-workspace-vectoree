# Vectoree 文档命名规范

> 角色：本文件与飞书产品知识库《文档规范》为同一规范的双份同步副本，团队与工程侧共同遵守、保持一致。
> 适用：所有 Vectoree 产品 / 产研文档（方案、需求、纪要、竞品、手册、复盘、规划）。

## 1. 抽象公式（结构规则，不含方括号）

```
产品/项目 - 文档类型 - 文档名称
```

- 分隔符统一为 ` - `（空格 + 短横 + 空格）。
- 抽象公式本身不带 `[]`：`[]` 是「可变 / 占位」标记，不在结构规则里出现。
- 文档类型从「受控词表」取（亦称文档分类），不自由发挥。
- 文档名称写具体语义，不用「方案1」「新建需求」等占位。

## 2. 模板占位形式（撰写指引中用 `[]` 标可变槽）

模板、how-to、规范示例里，用 `[]` 框住「需替换的变量槽」，提醒填写人代入实际值：

```
[项目名称] - [文档分类] - 文档名字
```

- `[]` = 可变 / 占位标记，仅出现在模板与撰写指引中。
- 产品 / 项目、文档类型都是可变槽，故都套 `[]`。
- 写真实文档时去掉 `[]`，直接填实际值。

## 3. 真实文档（实例，不带 `[]`）

落盘文档标题直接写实际值，不保留 `[]`：

```
Vectoree - 方案文档 - Onboarding 模板能力
```

- `[]` 是模板层占位符，实例化即删；真实标题保持干净，不夹标记符号。
- 产品前缀与文档类型都写实际词，不套 `[]`。

## 4. 文档类型受控词表

| 类型 | 含义 | 文件名缩写 |
|------|------|------|
| 方案文档 | 评审前方案设计 | solution |
| 需求文档 | PRD | prd |
| 会议纪要 | 会议记录 | meeting |
| 竞品分析 | 竞品调研 | competitor |
| 产品手册 | 对外产品文档 | manual |
| 复盘 | 项目 / 需求复盘 | retro |
| 规划 | 规划 / 路线图 | plan |
| 技术笔记 | 实现细节、踩坑记录与对接交接，PRD 的配套文档 | tech_note |

词表可扩展，新增类型需同步更新本表与飞书副本。

## 5. 示例

- `Vectoree - 方案文档 - Onboarding 模板能力`
- `Vectoree - 需求文档 - 模板一键安装`
- `Vectoree - 会议纪要 - 0901 产研体系对齐`

## 6. 标题与文件名分离

- 标题走中文规范（第 1 节公式，实际不带 `[]`）；落盘文件名走 ASCII 安全，沿用仓库英文 snake_case 习惯：`{type_en}_{name_en}.md`。
  - 例：标题 `Vectoree - 方案文档 - Onboarding 模板能力` ↔ 文件 `Onboarding_Template_Solution.md`
- 若需标题与文件名强绑定，可用 `YYYYMMDD-类型-名称.md` 便于排序（如 `20260901-方案文档-Onboarding模板能力.md`）。
