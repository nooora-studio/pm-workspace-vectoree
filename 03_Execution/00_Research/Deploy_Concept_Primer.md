# Vectoree - 调研报告 - Deploy 概念入门

> 性质：概念调研，不是方案。不涉及「我们做不做 / 用哪家底层」。
> 配套可视化：[Deploy 是怎么跑起来的](/cursor/stores/user/canvases/9c889a81-0d40-4d7f-9ab6-8ab354676b72/source.canvas.tsx)

---

## 1. 从笔记本到公网

本地跑项目时：磁盘上的代码 → 一条命令拉起进程 → 监听 `http://localhost:3000`。这个地址只在这台电脑有效；关机，世界上谁也打不开。

**Deploy** 是同一件事换地方：把程序（或构建出来的文件）放到一台不会被你合上的电脑上，再给它一个全世界 DNS 都能解析的名字（URL），通常还自动配上 HTTPS 证书。

所以「网页产品 deploy 后得到一个网页」里，访客真正得到的是三样绑在一起的东西：

1. 一个 URL（名字）
2. 一张证书（浏览器才显示小锁）
3. 能响应请求的后端（文件，或正在跑的程序）

---

## 2. 到底跑在什么上面（不只是虚拟机）

常见四层。越往下越像一台真电脑，越能跑「奇怪的常驻程序」，闲置时也越贵。

| 形态 | 类比 | 没人访问时 | 你在租什么 | 典型产品 |
|------|------|------------|------------|----------|
| **静态文件 + CDN** | 宣传册放到全世界报亭，无人值班 | 根本没有一台在跑的电脑 | 存储 + 流量 | GitHub Pages、Cloudflare Pages 静态模式 |
| **按请求唤醒（Serverless / Functions）** | 按小时酒店：有客人才开房 | 可以完全不跑（冷启动会慢一点） | 调用次数 × 执行毫秒 + 流量 | Vercel Functions、AWS Lambda、Cloudflare Workers |
| **容器（Container / Docker）** | 酒店标准间：行李是你的，水电和操作系统内核共用 | 默认可一直开，也可做成缩到 0 | CPU / 内存 × 小时 | Railway、Render、Fly、Coolify、Dokploy |
| **虚拟机（VM）** | 整租公寓：完整操作系统 | 开机就一直计费 | 整台规格 × 小时 | AWS EC2、阿里云 ECS、Replit Reserved VM |

**容器和虚机只记一句：** 虚机带完整操作系统，重、隔离强；容器共用宿主机内核，只隔离进程和文件系统，轻、启动快。2015 年后新 PaaS 几乎都用容器。对使用者体感很像：都有 CPU、内存、一个进程在听端口。

Vercel 这类「git push 出网址」的平台，对前端默认常常是：**构建一次 → 静态资源上 CDN，服务端逻辑切成函数按请求跑**。它不是给你一台你能 SSH 上去的虚机。

---

## 3. 点 Deploy 之后，通常经过两台「电脑」

1. **临时构建机**（用完即扔）：`npm install`、编译。失败则不上线。这笔钱叫 build minutes。
2. **长期运行处**：CDN 上的文件、或容器里的进程、或已注册的函数。这才是访客打到的「服务器」。
3. **起名**：分配 `xxx.平台.com`，签发证书。

构建失败时，旧版本往往还在线上，只是新版本没换上去。

## 4. 「自己填 URL 去 Deploy」是三件不同的事

URL 不是 U 盘路径，不能填一个网址就把应用存进去。URL 是电话簿里的**名字**。Deploy 先把应用放到机房，再决定哪个名字指向它。

| 人们说的「填 URL」 | 实际在做什么 | 能不能填任意网址 |
|--------------------|--------------|------------------|
| 部署完成后得到一个网址 | 平台**分配**子域，如 `my-app.vercel.app` | 你填不了，系统生成 |
| 填写自己买的域名 | **自定义域名**：你拥有 `myagent.com`，在面板填它，再去域名商加 CNAME | 只能填你拥有的域名，不能填 google.com |
| 填写 GitHub 仓库地址 | 告诉平台**代码从哪拉**。访问地址仍由平台生成 | 这是输入源，不是发布目标 |

自定义域名的固定步骤：买域名 → 在托管平台填 `app.mybrand.com` → 平台给出 CNAME 目标 → 你在阿里云/Cloudflare 等加上这条 DNS → 平台验证并自动申请证书 → 访客打开你的域名，实际仍是同一套已部署应用。

## 5. 成本怎么算

点 Deploy 往往不单独卖。钱在占用的资源上：

| 维度 | 计什么 | 谁容易中招 |
|------|--------|------------|
| 开机时长 | CPU/内存租了多少小时 | 虚机、常驻容器 |
| 请求与执行时间 | 调用次数 × 每次毫秒 | Functions / Autoscale |
| 流量 egress | 从机房流出多少 GB | 图片、全球访客（Vercel Hobby 含 100GB/月，2026-08 价目） |
| 构建分钟 | 每次发布编译多久 | 频繁 push |
| 磁盘 / 数据库 | GB 存储 | 通常算后端账，不算「部署费」 |
| 模型 Token | LLM 推理 | 网关钱包，和托管是两套账 |

闲置量级（示意，不是发票）：静态站接近 $0；函数也可以接近 $0；1 核 2GB 常驻容器/虚机常见每月数美元到二十美元。Vercel Pro 坐席 $20/人/月（2026-08），用量另计。

**模型费 ≠ 托管费。** 访客不打开页面时，Token 可以是 0；但常驻服务器仍在扣开机费。

## 6. 网页产品和 Agent 产品

Agent 不是一种新电脑，还是代码。差别是：有没有人打开网页时，它也必须自己干活。

| Agent 行为 | 要不要常开服务器 | 更接近哪种运行时 |
|------------|------------------|------------------|
| 用户打开网页才聊天 | 通常不要 | 静态前端 + 模型网关 API |
| 用户关闭网页就停止 | 不要 | 同上 |
| Slack/Webhook 随时可能打进来 | 要有一个公网入口能被叫醒 | 函数可以，但不能休眠太死 |
| Discord 机器人 24 小时在线 | 要 | 常驻容器或虚机 |
| 每天早上 9 点自动写日报 | 只要定时醒 | Cron / Scheduled，不必 24 小时 |

「网页里的 Agent」和「发布一个普通网页」在托管层可以完全相同：Deploy 出去的是门面，推理发生在网关。只有「没人看着也在跑」的 Agent 才强制需要 Compute 那一层。

---

## 7. 三句收口

1. Deploy 是把程序或文件放到机房，再给它一个公网名字。
2. 机房里那台「电脑」可能是虚机、容器、按次唤醒的函数，或根本没有电脑（纯文件）。
3. 自己填的网址，要么是代码仓库（输入），要么是你买来的域名（贴到已部署的应用上）；不能把应用部署进任意一个已存在的网页 URL。
