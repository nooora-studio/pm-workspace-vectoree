# [方案名称] 方案文档

> 用途：需求评审前对齐方向，供评审逐条拍板。
> 适用：中轻量需求；大型需求可在本骨架下扩展。

---

## 1. 背景概述
- **需求来源**：[哪次会议 / 哪个规划决策 / 哪份文档决定要改这个需求，附链接]
- **背景上下文**：[为什么现在做、当前业务 / 产品阶段]
- **关联**：[相关需求 / 项目 / 干系人]

## 2. 问题说明
- **目前存在的问题**：[具体痛点，谁受影响、现状为何不够好]
- **相关问题**：[由此衍生 / 关联的问题，避免只盯单点]
- **佐证**：[数据、用户反馈、竞品参照，可附链接]

## 3. 方案概述
- **整体思路**：[一句话 + 闭环：做什么 → 用户 / 业务得到什么]
- **关键共识**：[必须对齐的点，防止后面理解跑偏]

## 4. 方案说明
- **核心机制**：[方案怎么运作，主干逻辑]
- **模块 / 边界**：[涉及哪些部分；明确做 / 不做的边界]
- **分层视角（按需）**：[研发侧 / 用户侧；前置一次性 / 每次使用]

## 5. 方案详细拆解
- **分步实现**：[流程 / 步骤，用序号呈现]
- **关键设计**：[数据结构 / 接口 / 交互 / 异常分支]
- **配图（按需，只为降低理解成本而画）**：
  - 【图：主流程图】—— 用户 / 系统主链路
  - 【图：模块 / 架构图】—— 各部分关系
  - 【图：状态 / 时序图】—— 多角色或多步骤协作
  - 图表原则：流程图 / 架构图 / 时序图 / 状态图 / 对比表优先；说不清才画，不凑数

## 可选补充模块（按需选用，非必填）
> 以下为产品视角常见但不在你固定骨架里的模块；需求跨团队或较复杂时再补，不打乱上方主线。

### A. 目标与成功指标
- 业务目标 / 北极星 + 支撑指标（含口径）/ 非目标

### B. 范围边界
- 范围内（In-scope）/ 范围外（Out-scope）

### C. 风险与依赖
- 风险 / 冲突 / 口径 + 预案；依赖与前提

### D. 落地与排期
- 阶段节点 / 责任人 / 验收标准

### E. 验证状态
- 连通性已验证 / 端到端已跑通 / 待验证（逐项标记）
