# Vectoree 产品知识库

欢迎来到 Vectoree 产品知识库。本知识库是围绕 [Vectoree](https://vectoree.ai/)（一站式 Agent 开发与上线平台 / MaaS 平台）建立的产品管理与战略决策中枢。

## 📖 项目背景与愿景

在从 0 到 1 打造 Vectoree 的过程中，我们需要处理海量的产品逻辑拆解、竞品市场情报、商业模式推演以及高保真原型设计。本知识库的建立旨在：

1. **统一事实来源**：将散落的市场数据、竞品动态结构化沉淀为客观事实档案，消除团队信息差。
2. **支撑战略决策**：通过深度的产品拆解与调研分析，为 Vectoree 的路线图规划、功能选型及差异化打法提供坚实的依据。
3. **分离过程与结果**：建立清晰的知识管理边界，让个人的认知推演过程与团队最终的战略交付物互不干扰。

## 🎯 内容涵盖范围与导读

本知识库并不预设单一的线性阅读路径，而是作为一个全景式的资料库，服务于不同的业务关注点。你可以根据当前的目标，直接前往对应的领域：

- **关注「我们要做什么」**：如果你想了解 Vectoree 的顶层战略路线图、核心商业模式推演，或是查看基于竞品洞察得出的优化方向与产品原型，请重点探索 `01_Product`（内部产品层）。
- **关注「市场与对手在做什么」**：如果你需要获取关于底层基建巨头（如 Vercel, Supabase, Clerk）或直接竞品（如 Insforge）的详细客观情报与对比分析矩阵，请前往 `02_Knowledge`（外部事实层）。
- **关注「认知沉淀与推演逻辑」**：如果你对战略报告背后的思考推演过程、MaaS 平台的深度商业认知，或是日常的调研碎片感兴趣，可以浏览 `_Personal`（个人认知层）。
- **关注「知识库如何运转」**：如果你是本库的协作者，需要新建文档、了解目录规范与状态流转规则，请务必先阅读 `00_Meta`（规则与治理层）。

## 🗺️ 知识库架构概览

本知识库采用**「事实 · 产出 · 认知」**三层架构，所有文件按性质严格归类。避免过程文件与战略结果混淆。详细目录规范与生命周期管理，请参阅全局唯一结构标准：[00_Dir_Structure.md](file:///Users/yuke/Documents/pm-workspace-vect/00_Meta/00_Dir_Structure.md)。

### 01_Product — 内部产品层（事实与核心产出）
承载 [Vectoree](https://vectoree.ai/) 产品的既定事实与团队级、战略级产出。
- **核心内容**：产品战略洞察、版本路线图、深度拆解报告、高保真原型与 UI 资产、产品模块思维导图（HTML 可视化）。
- **Badcase 管理**：`01_Product/Badcase/` 收录劣质/异常案例（Badcase），含标准录入模板与汇总索引，用于质量闭环与回归沉淀。
- **入口**：`01_Product/`

### 02_Knowledge — 外部事实层（市场与竞品档案）
沉淀关于外部世界的客观事实，为核心战略产品决策提供弹药支撑。
- **核心内容**：包含 Insforge（直接竞品）及 OpenRouter、Clerk、Supabase、Vercel 等 4 家底层基建巨头（间接竞品）的全方位档案。
- **说明**：此模块不记录调研过程，仅沉淀各竞品的 Profile、Features、Pricing、SWOT 等结构化详细档案文件。
- **入口**：`02_Knowledge/00_Competitive/`

### 03_Execution — 产出层（决策与交付）
承载需求、方案、规划、会议、复盘等过程性交付物，是团队「决定了 / 交付了什么」的记录。
- **核心内容**：需求文档（PRD）、方案文档（Solutions）、规划 / 路线图、会议纪要、复盘。需求池（Backlog）当前在飞书多维表格维护，暂不落地工程。
- **入口**：`03_Execution/`

### 00_Meta — 规则与治理层
知识库的「规则手册」。
- **核心内容**：目录结构规范、协作流程、文档元数据（Front Matter）标准、[可视化结构图谱](file:///Users/yuke/Documents/pm-workspace-vect/00_Meta/Knowledge_Structure_Map.html)。
- **入口**：`00_Meta/`

### _Personal — 个人认知层（私有边界）
记录调研期间的过程性思考、学习笔记与非正式内容，不作为团队决策的直接事实依据。
- **核心内容**：MaaS 平台深度认知框架、日常调研日志、AI 协作工作台草稿、术语词典、个人周进度汇报。
- **入口**：`_Personal/`

## ⚙️ 核心协作规范摘要

为保持知识库的整洁与可检索性，请在新增内容时遵循以下基本准则：

1. **结构化元数据**：所有 Markdown 文档必须包含标准化的 YAML Front Matter（包含 title, status 等）。
2. **过程与结果分离**：个人的调研草稿放 `_Personal`，最终提炼的战略报告与事实才沉淀至 `01_Product` 或 `02_Knowledge`。
3. **状态流转**：明确使用 `DRAFT` (草稿) -> `REVIEW` (评审中) -> `FINAL` (定稿) -> `ACTIVE` (持续维护) 标注文档当前可信度。
