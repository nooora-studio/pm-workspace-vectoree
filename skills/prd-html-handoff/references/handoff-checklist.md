# 交付审计清单

每份 PRD 交付前逐条核对。每一条要么满足，要么修复，要么移进 §8 作为待确认项。**这份文件的存在意义就是防住隐性缺口。**

---

## A. 前端交付清晰度（§0）

| # | 检查项 | 为什么重要 |
| - | - | - |
| A1 | 交付物清单列出 HTML 文件或分支路径 | 没有它研发无法开工 |
| A2 | 写明如何查看（启动命令 + 路由，或直接打开） | 含需要登录态才能看到的页面怎么进 |
| A3 | **逐项列出所有 mock**：假登录、模拟延迟、写死的演示常量、localStorage key、演示切页面板、调试入口 | 最高危的遗漏项。演示数据被照抄进生产会同时造成数据污染和逻辑错误 |
| A4 | 不可信部分明确标注「禁止照抄」 | 演示面板与假会话绝不能进生产 |
| A5 | 写明 HTML 与本文档冲突时如何处理（停下确认） | 防止研发替产品做决策 |

## B. 范围精确度（§1、§3）

| # | 检查项 | 为什么重要 |
| - | - | - |
| B1 | 「不做」表存在且非空 | 研发最容易「顺手优化一下」越界的地方 |
| B2 | 每个页面 / 模块都列了路由与改动性质 | 研发据此导航 |
| B3 | 有列标明前端是否已交付 | 既防重复劳动，也防误以为有缺口 |
| B4 | **「需删除的现网逻辑」单独成节** | 漏删造成双入口；删错造成回归 |
| B5 | 明确不动的部分已列出 | 防止范围蔓延 |
| B6 | 影响面覆盖其他页面、服务、数据表、异步任务、第三方 | 总有东西被漏掉，异步任务与回调是高频漏项 |

## C. 规则的可判定性（§4、§6）

| # | 检查项 | 为什么重要 |
| - | - | - |
| C1 | 每条判断条件都指明读哪个字段、比什么值、时间窗口怎么算 | 「符合条件的用户」不是条件 |
| C2 | **每个枚举 / 状态字段的所有取值都列全并说明含义** | 前端每种视觉状态对应一个枚举值，漏一个研发就无法正确返回 |
| C3 | HTML 出现多种动态状态的地方都有状态机 | 不只后端流程，前端子状态也算 |
| C4 | **demo 把多种业务情况合并成一种视觉呈现的地方，PRD 已拆开** | demo 式交接中最高频、影响最大的缺陷 |
| C5 | 时序：每个异步操作都有时长上限与超时行为 | 「超时」不带数字无法实现 |
| C6 | 边界表每行都答齐四问：谁触发、系统怎么办、用户看到什么、数据留不留痕 | 只写「返回错误」不构成规格；留痕与否直接影响后续排查与对账 |
| C7 | 发放类 / 建关系类 / 发凭证类接口都声明了幂等要求 | 不写幂等，研发默认最简实现，线上重复发放 |
| C8 | 标出哪些校验必须前后端双写 | 前端校验是体验，服务端校验才是安全 |
| C9 | 每类数据的留存时长与到期行为已说明 | 额度与财务类数据有硬性要求 |
| C10 | 每条规则只定义一次，其他位置引用章节号 | 重复定义会漂移，研发无法判断哪份权威 |

## D. 页面级细节完整度（§5）

| # | 检查项 | 为什么重要 |
| - | - | - |
| D1 | 每个页面都有路由、文件路径、入口来源、离开方式、是否需登录 | |
| D2 | 位置用 HTML 里的 ①②③ 标记引用，不用相对描述 | 「左上角按钮」在 HTML 一改就失效 |
| D3 | 每个模块有展示规则、数据来源（字段名与类型）、交互逻辑 | |
| D4 | **每个数据区域都写了加载 / 空 / 错误 / 无权限四种状态** | demo 通常只实现正常路径，而这四种是真实故障高发区 |
| D5 | 用户可见文案逐字入表 | 研发要准确字符串，不是对字符串的描述 |
| D6 | 每页有研发交付要点（做什么、依赖、怎么算做完） | 让验收无歧义 |
| D7 | 可交互元素的禁用 / 加载 / 限额状态已说明 | 「反复点击没反应」必须写下来 |

## E. 埋点完整度（§7）

| # | 检查项 | 为什么重要 |
| - | - | - |
| E1 | 埋点目标写成要回答的问题 | 否则事件只会在那里堆积，什么也回答不了 |
| E2 | **成功度量节与埋点节的指标定义一致** | 两套定义等于两套都不可信 |
| E3 | 公共参数已定义（用户、组织、项目、来源、实验） | 没有它们漏斗无法拆分维度 |
| E4 | 每个页面与关键模块都有曝光事件 | |
| E5 | **成功与失败分别打点**，携带 `result` / `error_code` | 只打点击无法区分接口挂了和用户直接走了 |
| E6 | 链路追踪是编号序列，与流程节对齐，每步有流失定义 | |
| E7 | 埋点验收检查已写（如何验证事件上报、刷新与重复点击不重复上报） | |
| E8 | 正常路径与每条异常路径都有对应事件 | 异常事件是问题被发现的途径 |

## F. 文档卫生

| # | 检查项 |
| - | - |
| F1 | 无括号式自我标注（「（重点）」「（注意）」「（专门强调）」） |
| F2 | 无内部调试痕迹、用户名、版本迭代备注 |
| F3 | 变更记录只记交付定稿之后的改动 |
| F4 | 可选模块要么填完要么整节删除，不留空壳 |
| F5 | 有图只为降低理解成本，无凑数图表 |
| F6 | 待确认项带责任人与截止时间，否则不可执行 |
